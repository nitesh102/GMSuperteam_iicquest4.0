2.  ARCHITECTURE & DATA FLOW
================================================================================

2.1  High-Level Architecture

  Browser ──Inertia.js──▶ Laravel 12 (REST/JSON) ──Eloquent──▶ MySQL
     │                        │
     │                        ├── Controllers (CRUD)
     │                        ├── Middleware (Auth, Session, HandleInertia)
     │                        ├── Spatie Permissions (RBAC)
     │                        ├── Validation (inline)
     │                        └── Gemini AI Service (ComplaintAiService)
     │
     └── Vue 3 SPA (Composition API)
         ├── Pages/       (per-route page components)
         ├── Components/  (shared — Modal, Sidebar, DataTable)
         ├── Layouts/     (AuthenticatedLayout, AdminLayout)
         └── Inertia App  (app.js + Ziggy routes)

2.2  Data Flow Patterns

  Page visit:          GET /{route} → Controller::index() → Inertia::render()
  Form create:         POST /{route} → Controller::store() → AI analysis → redirect + flash
  Form update:         PUT /{route}/{id} → Controller::update() → redirect + flash
  Delete:              DELETE /{route}/{id} → Controller::destroy() → redirect + flash

2.3  AI Flow (store only)

  POST /complaints
    → validate (title, description, category_id nullable, location, lat/lng, attachments)
    → spam filter (isObviousSpam — deterministic regex, runs BEFORE AI)
    → load departments + categories
    → Gemini API call (constrained to valid dept/category enum, structured JSON)
    → catch Exception → simulation fallback (keyword priority + summary truncation)
    → if user provided category_id: preserve it (skip AI department/category determination)
    → if no category_id: firstOrCreate Department + ComplaintCategory from AI result
    → create complaint record
    → create complaint_ai_analyses row
    → store attachments to public disk
    → redirect with success flash

3.  CONVENTIONS & PATTERNS
================================================================================

3.1  Naming Conventions
─────────────────────
  Models             : Singular, PascalCase (e.g., ComplaintCategory)
  Controllers        : Singular, PascalCase + "Controller" suffix
  Migrations         : snake_case (e.g., create_complaint_categories_table)
  Routes             : kebab-case (e.g., complaint-categories.index)
  Vue Pages          : Singular, PascalCase, nested under folder matching route prefix
  Vue Modals         : PascalCase, co-located with page in Pages/{Module}/

3.2  Model Convention
─────────────────────
  - Extends Illuminate\Database\Eloquent\Model
  - Uses HasFactory trait
  - $fillable array for mass-assignment protection
  - casts() method for attribute casting
  - SoftDeletes trait if table has deleted_at column
  - Define relationships as BelongsTo/HasMany/HasOne methods

3.3  Controller Convention
──────────────────────────
  - Extends App\Http\Controllers\Controller
  - Inertia\Response / RedirectResponse return types
  - Inline $request->validate() (extract to FormRequest when complex)
  - CRUD methods: index (Inertia::render), store (redirect), update (redirect), destroy (redirect)
  - Flash messages via ->with('success', '...') on redirect
  - ComplaintController: dedicated Create page (not modal) for create; modal for edit

3.4  Inertia Page Convention
─────────────────────────────
  - <script setup> Composition API
  - Import layout for authenticated pages
  - <Head> component for page title
  - Local reactive `items` ref initialized from usePage().props.{entity}
  - Props sync watch: watch(() => usePage().props.{entity}, ...) after redirect
  - Flash toast watch: watch(() => usePage().props.flash?.success, ...) for reactive messages
  - Computed properties for filter/sort/paginate on local `items`
  - Optimistic CRUD with router.delete()/router.post() and error fallback router.reload()

3.5  Route Convention
─────────────────────
  - Named routes using ->name() for Ziggy JS access (route() helper)
  - Resource routes with except(['create', 'edit', 'show']) — exceptions for complaints.create/show
  - Grouped under 'auth' middleware
  - Kebab-case route parameters

3.6  Status Transition State Machine
────────────────────────────────────
  Valid transitions (ComplaintController::STATUS_TRANSITIONS):

    submitted    → under_review, rejected
    under_review → assigned, rejected, submitted
    assigned     → in_progress, under_review, rejected
    in_progress  → resolved, rejected, assigned
    resolved     → closed, in_progress
    rejected     → submitted
    closed       → []

  Enforcement added in update(): throws ValidationException on invalid transition.

5.  KNOWN BUGS & RESOLUTIONS (COMPLETE LOG)
================================================================================

  BUG-001: DELETE /departments/{id} → 404
    Root cause: Empty departments table; route model binding couldn't resolve ID.
    Fix: Created DepartmentSeeder with 8 realistic departments, called from DatabaseSeeder.
    Status: RESOLVED.

  BUG-002: Temp negative-ID items in list after optimistic create
    Root cause: Optimistic create adds item with `id: -Date.now()`. On redirect, Inertia
    reuses component (no re-mount), so `items` ref retains temp item.
    Fix: watch() on usePage().props.{entity} syncs items after redirect.
    Status: RESOLVED.

  BUG-003: Flash messages not showing on edit/delete
    Root cause: Component reuse means <script setup> doesn't re-run.
    Fix: watch() on usePage().props.flash?.success with { immediate: true }.
    Status: RESOLVED.

  BUG-004: PHPUnit "could not find driver" (SQLite)
    Root cause: php pdo_sqlite extension not installed on this VM.
    Fix: Edited phpunit.xml to use MySQL + civicsense_testing database.
    Status: WORKAROUND.

  BUG-005: Gemini package not installed
    Root cause: ComplaintAiService imported Gemini namespace but package missing from composer.json.
    Fix: composer require google-gemini-php/laravel
    Status: RESOLVED.

  BUG-006: aiAnalysis() relationship missing on Complaint model
    Root cause: Controller called $complaint->aiAnalysis()->create() but relationship not defined.
    Fix: Created ComplaintAiAnalysis model with HasOne relationship.
    Status: RESOLVED.

  BUG-007: ai_analyses table schema mismatch
    Root cause: Controller passed ['summary', 'raw_response'] but table has different columns.
    Fix: Updated controller to match migration columns.
    Status: RESOLVED.

  BUG-008: Service used deprecated withConfig() array API
    Root cause: google-gemini-php/laravel v2.0 requires withGenerationConfig() + Schema objects.
    Fix: Rewrote service to use v2.0 API with proper types.
    Status: RESOLVED.

  BUG-009: category_id overridden by AI on complaint creation
    Root cause: Controller always overrode user's category_id with AI-detected category.
    Fix: Now preserves user-selected category_id when provided; AI only determines
    category when no category_id is sent. Added 'category_id' => ['nullable', 'exists']
    to store validation.
    Status: RESOLVED (2026-06-11).

  BUG-010: Spam filter blocked validation tests
    Root cause: isObviousSpam() ran before category_id validation; test descriptions
    like "Test description." triggered the filter before validation errors could surface.
    Fix: Validation now runs first (includes category_id nullable|exists); spam filter
    runs after. Test updated to assert spam error for non-civic submissions.
    Status: RESOLVED (2026-06-11).

  BUG-011: Invalid status transition in test
    Root cause: test_complaint_can_be_updated tried 'submitted' → 'in_progress' which
    is not a valid transition (must go through under_review → assigned).
    Fix: Factory now creates complaint with 'under_review' status, test transitions to 'assigned'.
    Status: RESOLVED (2026-06-11).

  BUG-012: Long text triggered spam filter in AI summary test
    Root cause: "Lorem ipsum" text matched meta commentary regex pattern in spam filter.
    Fix: Changed test data to use genuine civic description with repeated civic context.
    Status: RESOLVED (2026-06-11).

6.  PERFORMANCE OPTIMIZATIONS APPLIED
================================================================================

  6.1  Client-Side (Frontend)
  ─────────────────────────────
    • Optimistic CRUD: Local mutations instantly applied; HTTP fires in background.
    • Props Sync Watch: Prevents temp-ID persistence after redirect.
    • Flash Toast: Reactive watch with 4s auto-dismiss, click-to-dismiss.

    • Vite code splitting: Each page is a separate chunk (lazy-loaded).

  6.2  Server-Side (Backend)
  ─────────────────────────────
    • Soft deletes prevent expensive cascade operations.
    • Eager loading: ->with('department'), ->with('attachments'), etc. prevent N+1.
    • Spatie permission caching (built-in).
    • Simulated AI fallback avoids retry on API failure.

  6.3  Database
  ────────────────
    • MySQL InnoDB with foreign key constraints.
    • Soft deletes on all complaint-related tables.
    • Indexed primary/foreign keys (indexes pending on status, priority, created_at, due_at).

7.  PERFORMANCE & UI RESPONSIVENESS ANALYSIS (2026-06-11)
================================================================================

7.1  Critical Issues Found

  CONTROLLER - No Pagination (HIGH)
    File: app/Http/Controllers/ComplaintController.php:51
    Issue: Complaint::with(...)->get() loads ALL complaints into memory.
    As dataset grows, this will exhaust PHP memory. All records sent to Inertia.
    Fix: Add ->paginate(25) and handle Inertia pagination in Vue.

  CONTROLLER - Synchronous AI Call Blocks HTTP (HIGH)
    File: app/Http/Controllers/ComplaintController.php:107
    Issue: Gemini API call is synchronous with 60s timeout. Blocks PHP-FPM process.
    Fix: Dispatch AI analysis to a queue job (ProcessComplaintAi::dispatch()).

  CONTROLLER - No Caching of Reference Data (HIGH)
    File: app/Http/Controllers/ComplaintController.php:55-56, 73-74, 103-104
    Issue: Departments and categories fetched from DB on every request.
    Fix: Use Cache::remember('departments.list', 86400, ...).

  FRONTEND - Blob URL Memory Leak (HIGH)
    File: resources/js/Pages/Complaint/Create.vue:23,29,54
    Issue: URL.createObjectURL() creates blob URLs that are NEVER revoked.
    Fix: Call URL.revokeObjectURL() in removeFile(), on success, and onUnmounted.

  FRONTEND - No Debounce on Search (HIGH)
    Files: Complaint/Index.vue:421, AdminDataTable.vue:79
    Issue: Search input filters entire dataset synchronously on every keystroke.
    Fix: Add debounce (already done in SearchFilter.vue — need to port pattern).

  FRONTEND - Missing :disabled on Auth Submit Buttons (HIGH)
    Files: Register.vue, VerifyEmail.vue, ConfirmPassword.vue, ForgotPassword.vue, ResetPassword.vue
    Issue: Buttons show opacity-25 but disable attribute not set — double-submit possible.
    Fix: Add :disabled="form.processing" to all PrimaryButton instances.

  FRONTEND - Empty handleSearch in Navbar (HIGH)
    File: resources/js/Components/Navbar.vue:254
    Issue: Search function is empty — UI shows search but it does nothing.

  FRONTEND - Unsafe document.body.style.overflow (HIGH)
    File: resources/js/Layouts/AdminLayout.vue:14,22,46
    Issue: Direct DOM mutation without SSR guard (typeof document check).
    Fix: Wrap in typeof document !== 'undefined' guard.

  FRONTEND - Chart.js Bundled in Main Chunk (HIGH)
    Issue: chart.js + vue-chartjs imported statically in Dashboard, bundled into main
    app chunk despite being used on ONE page. Adds ~65KB+ to every page load.
    Fix: Lazy-load chart components or use manual code-splitting in vite.config.js.

7.2  Medium Issues Found

  DB - Missing Database Indexes (HIGH)
    Tables: complaints (citizen_id, category_id, assigned_to, current_status, priority, created_at, due_at)
    Impact: Full table scans on dashboard COUNT queries, escalation queries, sort operations.
    Fix: Add migration with indexes on all foreign keys + frequently filtered columns.

  DB - Database Cache/Session/Queue Drivers (MEDIUM)
    File: .env — CACHE_STORE=database, SESSION_DRIVER=database, QUEUE_CONNECTION=database
    Issue: All three use database tables, adding overhead for every operation.
    Fix: Use file/redis cache, file/redis sessions, redis queue in production.

  DB - Dashboard 4x COUNT Queries (MEDIUM)
    File: routes/web.php:25-30
    Issue: Each stat counter executes a separate SQL COUNT query.
    Fix: Combine into a single SELECT with SUM(CASE ...) for all four counters.

  FRONTEND - Flash Timer Memory Leaks (MEDIUM)
    Files: Complaint/Index.vue, Complaint/Create.vue, Complaint/Show.vue, ComplaintCategory/Index.vue
    Issue: setTimeout in flash watchers has no onUnmounted cleanup.
    Fix: Add onUnmounted(() => clearTimeout(flashTimer)) to all components.

  FRONTEND - Un-debounced Resize Handlers (MEDIUM)
    Files: AdminLayout.vue:39, AuthenticatedLayout.vue:60
    Issue: window resize fires on every pixel change, triggering reactive recomputation.
    Fix: Add debounce (e.g., 150ms) to resize handlers.

  FRONTEND - Missing Transition Animations (MEDIUM)
    Files: AdminLayout.vue (mobile sidebar), Modal.vue (backdrop), AdminSidebar.vue (mobile drawer)
    Issue: Elements appear/disappear instantly with v-if — no fade/slide transitions.
    Fix: Wrap in <Transition> component.

  FRONTEND - Hardcoded Admin Credentials in Login.vue (HIGH - Security)
    File: resources/js/Pages/Auth/Login.vue:234-238
    Issue: email: 'admin@gmail.com', password: 'admin@123' exposed in frontend source.
    Fix: Remove hardcoded credentials — use placeholder text only.

  FRONTEND - Missing loading="lazy" on Complaint Images (HIGH)
    File: resources/js/Pages/Complaint/Show.vue:259-262
    Issue: All attachment images load immediately regardless of viewport position.
    Fix: Add loading="lazy" attribute to <img> tags.

  FRONTEND - Duplicated Flash Message Markup (LOW)
    Issue: Flash toast HTML duplicated across 4+ components.
    Fix: Extract to reusable FlashMessage component.

7.3  Security Issues Found

13. AI SERVICE ARCHITECTURE (DETAILED)
================================================================================

  ComplaintAiService (app/Services/ComplaintAiService.php):
    • Model: gemini-2.0-flash
    • Library: google-gemini-php/laravel v2.0
    • Structured JSON output via ResponseMimeType::APPLICATION_JSON + Schema objects
    • Constrained to valid departments/categories via enum in JSON schema (prevents hallucination)
    • Accepts up to 3 images as Blob attachments (first 3 of max 5)
    • Returns: is_spam, spam_reason, department_name, category_name, priority, summary

  Fallback Chain:
    try { Gemini API } → catch (\Exception) { simulation methods }

  Simulation Methods (ComplaintController private):
    simulatePriority($lower): regex keyword matching → emergency/high/medium/low
    simulateSummary($description): strip_tags + truncate at 200 chars
    Fallback returns null for department_name/category_name → controller skips AI category

  Category Resolution:
    User provided category_id → preserved (skip AI department/category)
    No category_id provided → AI result → firstOrCreate Department + ComplaintCategory

  MIME Mapping:
    image/png  → MimeType::IMAGE_PNG
    image/webp → MimeType::IMAGE_WEBP
    image/gif  → MimeType::IMAGE_PNG  (GIF sent as PNG — known limitation)
    default    → MimeType::IMAGE_JPEG

14. SPAM FILTER (isObviousSpam)
================================================================================

  Location: app/Http/Controllers/ComplaintController.php:269-402
  Phase: Runs BEFORE AI call but AFTER input validation
  Rules:
    1. Title made entirely of filler/greeting/test/stop words → spam
    2. No genuine civic keywords in title or description AND desc < 120 chars → spam
    3. Long desc without civic keywords checked for meta/test commentary → spam
    4. Has civic keywords but description is meta-commentary (e.g., "this is a test") → spam

  This prevents obvious spam without consuming Gemini API quota. Complex regex with
  ~300 keywords across roads, water, electricity, waste, lighting, parks, buildings,
  trees, animals, emergency, and general civic services.
